# Data Notes

## What data is included in this repository

This repository includes **only synthetic / generated data** created specifically for the PoC.
No real agency certificate data, real domain names, or production credentials are included.

### Synthetic certificate inventory

- `generated_certificates/certificate_inventory.csv` — 20 synthetic certificate records
- Generated by running `python generate_dummy_certificates.py --count 20`
- Simulates realistic spread across 8 fictional Mississippi agency names, 5 issuers, 3 environments
- All domain names are example/placeholder values (e.g., `portal.mdot.ms.gov`)
- All expiration dates are set to exercise all lifecycle states (expired, critical, expiring_soon, active)

### Self-signed certificate files

- `generated_certificates/certs/*.crt` — Real OpenSSL self-signed certificates (RSA 2048-bit)
- These are freshly generated dummy certs with no connection to any real agency or domain
- They are included so the cert parsing code works end-to-end in the sandbox

### What is NOT included

- Real SSL/TLS certificates from any Mississippi agency
- Private keys (`.key` files are gitignored and must never be committed)
- CSR files (`.csr` files are generated at runtime and gitignored)
- Real agency data, personally identifiable information, or operational credentials

## Data schema

The certificate record schema is designed to be DynamoDB-compatible. See `docs/architecture.md` for the full field list. Partition key: `certificate_id` (e.g., `CERT-006`).

## Live AWS data stores (active in PoC)

Although all certificate data is synthetic, the following AWS services are actively used
and contain PoC-generated data:

- **Amazon DynamoDB** — 5 tables storing certificate records, notifications, agent jobs, settings, and email log
- **Amazon S3** — Two buckets storing CSR files, issued certificates, and PFX bundles:
  - `mock-certificate-data` — certificate inventory sync
  - `certificate-data-processed1` — renewal job output

These services use real AWS resources in the `us-east-1` region under the project's AWS account.
No real agency certificate data is stored — all records are synthetic test data generated for the PoC.
